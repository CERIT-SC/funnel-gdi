# AGENTS.md

Instructions for coding agents working on funnel-gdi, the GDI fork of
[calypr/funnel](https://github.com/calypr/funnel) (Go module
`github.com/ohsu-comp-bio/funnel`). What the fork adds and why is in
[GDI-FEATURES.md](GDI-FEATURES.md); deployment in [DEPLOYMENT.md](DEPLOYMENT.md);
versioning and the release checklist in [RELEASING.md](RELEASING.md).

## Commands

| Command | What it does |
|---|---|
| `make lint` | golangci-lint v2 with `.golangci.yml` (govet, misspell, gofmt, goimports), run with the Go version from `go.mod` (`GOTOOLCHAIN`), as in CI |
| `go build ./...` | Compile everything |
| `make test` | `go test` on all packages. The Postgres tests use testcontainers and need a running Docker. |
| `make test-coverage` | `make test` with `-coverpkg=./...`, then `scripts/coverage` prints coverage per package (`build/coverage/merged.out`); `COVERAGE_MIN=<percent>` fails below it. Generated code and `tests/` helpers are not counted. |
| `make start-s3` | S3-compatible test server (versitygw) on `localhost:9000`, key `fakekey`, secret `fakesecret` |
| `make test-<backend>` | Component tests against a real backend (`start-<backend>` starts its container first), e.g. `make start-postgres test-postgres`. `COVER_DIR=<dir>` writes a coverage profile per test run into `<dir>`. |
| `make website-versions` | Build the documentation site (Hugo) and check its links. Needs `hugo`. |
| `make build` | Build the `funnel` binary |
| `make build-cover` | Build `funnel` with coverage instrumentation of all packages (acceptance tests) |

Tools: Go from `go.mod`, golangci-lint v2.11.4 (`go install github.com/golangci/golangci-lint/v2/cmd/golangci-lint@v2.11.4`, built with the `go.mod` Go version), Docker, Hugo (docs only), Helm (chart only).

## Verification chain

Run after every change, in this order:

1. `make lint`
2. `go build ./...`
3. `make test`
4. For changes to documentation (`*.md`, `website/`): `make website-versions`

CI (`.github/workflows/tests.yaml`) runs the same tests with `-coverpkg=./...` (job `unitTest`), the backend component tests (job `backendTests`: `make start-<backend> test-<backend> COVER_DIR=…` for postgres, mongodb, elasticsearch, badger, dynamodb, datastore, kafka, pubsub, generic-s3, ftp) and merges their coverage (job `coverage`): per-package report in the job summary, artifact `coverage` with the merged profile and an HTML report, and a failure below `COVERAGE_MIN`.

Acceptance tests (`.github/workflows/acceptance.yaml`) run against a binary built with `make build-cover`; each suite (called workflows `compliance.yaml`, `nextflow.yaml`, `integration-tests.yaml`) stops Funnel with SIGINT so it writes its coverage to `GOCOVERDIR`, converts it with `go tool covdata textfmt` and uploads a `coverage-acceptance-*` artifact. The `coverage` job merges them (artifact `acceptance-coverage`) and fails below `ACCEPTANCE_COVERAGE_MIN`.

Changes to `.github/workflows/*` can only be verified by a CI run (push a branch / open a PR); check the YAML locally by running the commands the workflow runs.

## Layout

- `server/` gRPC + HTTP gateway (TES API, auth, audit), `tes/` TES types, validation and client, `worker/` task execution, `compute/<backend>/` schedulers, `storage/` input/output backends, `database/<backend>/` task stores, `config/` config (Protobuf, `config/config.proto`), `cmd/` CLI (cobra), `webdash/` web dashboard (React, bundled into `webdash/web.go`).
- `tests/` end-to-end and backend tests (`tests/core`, `tests/scheduler`, …) plus their helpers (`tests/funnel_utils.go`, `tests/*.config.yml`).
- `deploy-guide/kubernetes/` the official Helm chart. `deployments/` holds upstream scripts that the fork does not test.
- `website/` documentation site (Hugo). `scripts/` release and docs helpers.

## Conventions

- Tests: standard `testing` package next to the code (`*_test.go`); shared helpers in a `*_test.go` helper file of the package, or in `tests/` for end-to-end tests. Throwaway probe tests are `<pkg>/probe_<topic>_test.go` and are deleted afterwards. No real network in unit tests (`httptest`).
- Library sources are in the module cache: `$(go env GOMODCACHE)/<module>@<version>/`.
- Match the surrounding code; generated code is regenerated, not edited (see INV-1 and the commands in GDI-FEATURES.md → "Keeping in sync with upstream").

## Invariants

- **INV-1** Never edit generated files: `*.pb.go`, `*.pb.gw.go`, `*_grpc.pb.go`, `webdash/web.go`, `*/internal/bundle.go` (go-bindata), `mock_*.go` (mockery). Change the source and regenerate.
- **INV-2** `CHANGELOG.md` is upstream's and stays untouched. GDI changes go into `CHANGELOG-GDI.md` under the unreleased version.
- **INV-3** `website/content/gdi/{deployment,changelog,features,release-policy,security}.md` are generated by `website/scripts/sync-gdi-docs.py` and gitignored. Edit the root documents instead.
- **INV-4** No new root `.md` files beyond the existing ones.
- **INV-5** Keep the "Documentation version: …" lines in `README.md` and `DEPLOYMENT.md` (checked by `scripts/check-docs-version.sh`).
- **INV-6** Every fork-only file or feature is listed in `GDI-FEATURES.md`.
- **INV-7** The official Helm chart is `deploy-guide/kubernetes`.
- **INV-8** TES API behaviour stays compliant: gRPC/HTTP status codes and response shapes do not change (TES compliance suite, `.github/workflows/compliance.yaml`, run by `acceptance.yaml`).
- **INV-9** No new Go or npm dependencies without the maintainer's approval.
- **INV-10** GitHub Actions are pinned to a commit SHA with a version comment, as in `.github/workflows/tests.yaml`.
- **INV-11** Coverage gates (`COVERAGE_MIN`, `ACCEPTANCE_COVERAGE_MIN`) may only be raised, never lowered.
- **INV-12** The web dashboard stays ES2018 / Chrome 64+ (see DEPLOYMENT.md → "Supported and tested platforms").
